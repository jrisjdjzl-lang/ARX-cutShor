# ARX-cutShor — منصة أتمتة إنتاج ونشر YouTube Shorts

منصة برمجية معيارية متكاملة لأتمتة اكتشاف الفيديوهات المصدر من **Google Drive**، والتحقق من صلاحيتها، وتقسيمها ذكياً إلى مقاطع قصيرة متوافقة مع **YouTube Shorts (9:16)**، وإضافة الهوية البصرية للقناة، وتوليد بيانات النشر العربية (العناوين، الأوصاف، الهاشتاغات)، وجدولة نشرها ورفعها عبر **YouTube Data API v3** الرسمية مع حماية صارمة من التكرار أو النشر العام غير المقصود.

---

## 1. المميزات الأساسية

* **تكامل رسمي مع Google Drive API v3**:
  * الاعتماد على المعرفات الثابتة للمجلدات والملفات (`drive_file_id`) وبصمة `MD5` وليس الأسماء وحدها.
  * التحقق من اكتمال رفع الملف وصلاحية امتداده وحجمه قبل التنزيل.
  * تجنب إعادة تنزيل الملف إذا وُجدت نسخة محلية سليمة ومطابقة للبصمة.
* **محرك معالجة وتقسيم فيديو متقدم (FFmpeg)**:
  * دعم صيغ `MP4`, `MOV`, `MKV`, `WebM`.
  * استخراج المدة، الدقة، معدل الإطارات، الترميز، نسبة الأبعاد، وحالة القناة الصوتية (مع توليد مسار صوتي صامت تلقائياً للفيديوهات الصامتة).
  * 4 أوضاع تقسيم:
    1. `fixed`: مدة ثابتة مع معالجة ذكية للجزء الأخير لتجنب المقاطع القصيرة جداً.
    2. `scene`: تقسيم مستند إلى تغير المشاهد (`Scene Detection`).
    3. `manual`: نقاط بداية ونهاية يدوية.
    4. `hybrid`: تقسيم هجين يجمع بين المدة المستهدفة وأقرب نقطة تغير مشهد.
* **قالب الفيديو والهوية البصرية (Branding Template)**:
  * تحويل تلقائي إلى أبعاد Shorts العمودية (`1080x1920` بنسبة `9:16`).
  * إضافة شعار القناة، مقدمة (`Intro`)، خاتمة (`Outro`)، شارة رقم الجزء، ونصوص عربية (`RTL`) للاشتراك والإعجاب في مناطق آمنة لا تغطي محتوى الفيديو.
  * كل عنصر في القالب اختياري بالكامل ويمكن تعطيله دون تعديل الشيفرة.
  * التزام صارم بحقوق النشر: لا يتضمن أي آليات تحايل على `Content ID`، ويفرض مراجعة يدوية إذا كانت حالة الحقوق غير مؤكدة.
* **توليد العناوين والأوصاف والهاشتاغات**:
  * قوالب مخصصة لكل سلسلة مع ترقيم تلقائي للأجزاء ومنع تكرار الهاشتاغات.
  * يعمل محلياً بنسبة 100% دون الحاجة إلى اشتراك ذكاء اصطناعي مدفوع، مع توفير واجهة اختيارية قابلة للربط بمزود AI عند الرغبة.
* **جدولة النشر والرفع إلى YouTube Data API v3**:
  * تحديد الحد اليومي، أيام وساعات النشر، المنطقة الزمنية، والفاصل الأدنى بين المقاطع.
  * آلية مصالحة الحالة (`State Reconciliation`) قبل إعادة المحاولة لمنع رفع المقطع مرتين إذا انقطع الاتصال بعد نجاح الرفع.
  * وضع `DRY_RUN` ووضع الاختبار (`Private / Unlisted Testing`) لمنع أي نشر عام أثناء الاختبار الأولي.
* **واجهة إدارة ويب عربية (RTL)**:
  * لوحة تحكم محلية محمية تضم 7 أقسام: `Dashboard`, `Sources`, `Processing Queue`, `Templates`, `Publishing Schedule`, `Settings`, `Logs`.

## 2. المتطلبات التقنية

* **نظام التشغيل**: macOS أو Linux أو Windows.
* **Python**: الإصدار `3.11+` (مُختبر على `Python 3.14`).
* **FFmpeg**: يتم توفيره تلقائياً عبر حزمة `imageio-ffmpeg` المضمنة أو عبر `ffmpeg` المثبت في النظام.
* **قاعدة البيانات**: `SQLite 3` (مضمنة في Python).

## 3. طريقة التثبيت السريع

```bash
# 1. إنشاء البيئة الافتراضية وتفعيلها
python3 -m venv .venv
source .venv/bin/activate

# 2. تثبيت المكتبات المطلوبة
pip install -r requirements.txt

# 3. نسخ ملف الإعدادات البيئية
cp .env.example .env
```

للتفاصيل الكاملة راجع [INSTALLATION.md](INSTALLATION.md) و[CONFIGURATION.md](CONFIGURATION.md).

## 5. طريقة تشغيل وضع `DRY_RUN` وأوامر النظام

في وضع `DRY_RUN=true` (المفعل افتراضياً):
* لا يتم رفع أي فيديو فعلياً إلى يوتيوب ولا استهلاك حصص النشر.
* تتم معالجة الفيديو محلياً، وحساب المواعيد، وحفظ تقارير JSON في `data/reports/`.

```bash
# فحص البيئة والإعدادات
.venv/bin/python -m arx_cutshor.cli audit

# معالجة ملف فيديو محلي في وضع الاختبار DRY_RUN
.venv/bin/python -m arx_cutshor.cli process --local-file path/to/video.mp4 --dry-run

# تشغيل دورة كاملة (اكتشاف -> معالجة -> جدولة -> محاكاة نشر -> تقرير)
.venv/bin/python -m arx_cutshor.cli run-cycle --dry-run

# تشغيل لوحة الإدارة العربية (RTL) محلياً
.venv/bin/python -m arx_cutshor.cli serve --host 127.0.0.1 --port 8000
```

## 7. حدود التشغيل المجاني والقيود المعروفة

1. **حصة YouTube Data API v3 المجانية**:
   * تمنح Google حصة افتراضية قدرها `10,000` وحدة يومياً لكل مشروع.
   * عملية رفع فيديو واحدة (`videos.insert`) تستهلك `1,600` وحدة، ما يعني حداً أقصى يبلغ **6 عمليات رفع يومياً** ضمن الحصة المجانية الافتراضية. يلتزم المجدول في `ARX-cutShor` بهذا السقف تلقائياً.
2. **بيئة GitHub Actions**:
   * GitHub Actions خدمة تشغيل مهام دورية (`Cron Workflows`) وليست خادماً دائماً (`24/7 Daemon`).
   * بيئة التشغيل في GitHub Actions مؤقتة (`Ephemeral`)، ولذلك صُمم النظام ليعتمد على Google Drive كمصدر للحقيقة وعلى مصالحة الحالة عبر YouTube API قبل الرفع. للحصول على تشغيل مستمر `24/7` بقاعدة بيانات SQLite محلية دائمة، يُنصح بتشغيل النظام على جهاز محلي أو خادم صغير (`VPS`).
